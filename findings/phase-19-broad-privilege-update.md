# Phase 19 — Broad privilege surface and runtime-boundary update

Date: 2026-08-10 (Asia/Taipei)

Scope: broaden the search beyond HOME. The target is any complete, reproducible
path that could obtain sufficient authority to change Fire Launcher state,
package/component state, user policy, persistent system state, recovery/OTA
state, kernel-driver state, UID 0, or kernel memory. This phase is host-only.

## Executive result

**Confirmed:** the saved PS7331 corpus still contains no complete ordinary APK
or ADB shell path of the form:

```text
ordinary caller
  -> accepted permission / SELinux / service-manager gate
  -> trusted identity or trusted user scope
  -> Fire package-state / HOME / UID 0 / partition / kernel-memory sink
```

**Confirmed:** the KFT transaction-3 implementation is a real trusted-side
writer. Its static sink is `enableKftLauncher(UserInfo)` →
`tryEnableKftLauncherComponent(UserInfo)` → Tahoe FreeTimeLauncher enabled and
Fire Launcher/Launcher3 disabled for the supplied `UserInfo.id`. This does not
establish that an ordinary caller can reach the transaction, select User 0, or
pass PackageManager's protected-package and cross-user checks. Evidence:
`P19A-001`, `P19D-KFT-002`.

**Confirmed:** the Amazon PackageManager facade preserves Binder caller
identity while delegating to the standard PackageManager/IPackageManager path;
the facade is not, by itself, a system-UID confused deputy. Evidence from
Phase 18 remains authoritative; Phase 19 did not replay the route.

**Strong evidence:** PS7331 has recovery/updater capability and multiple MTK
driver capabilities, but the saved evidence does not close a low-privilege
caller, policy, identity, and runtime-effect chain. Capability is not caller
reachability. Evidence: `P19B-01`–`P19B-09`, `P19C-C01`–`P19C-C11`.

**Disproved, bounded:** the named historical routes reconciled in Phase 1–18
do not justify repeating the same HOME, preferred-activity, Accessibility,
KFT, private Binder, OTA, recovery, driver, or exploit tests. Evidence:
`P19D-HOME-001`–`P19D-ACCESS-006` and the companion reconciliation CSV.

**No device mutation:** Phase 19 performed no Binder transaction, driver open
or ioctl, OTA/recovery execution, reboot, package/settings mutation, Fire
Launcher mutation, root attempt, partition write, or SELinux change. Rollback
for this phase is therefore `NOT_APPLICABLE`.

## Key findings

### 1. KFT is a real writer, not an ordinary-app bypass

The important distinction is between a writer and a reachable writer. Static
code shows the writer can alter launcher state for a `UserInfo.id`. Existing
runtime evidence already showed ordinary User-0 and User-10 callers being
rejected by PackageManager/cross-user gates; Phase 19 did not repeat those
tests. The missing proof is the legitimate production client and its complete
permission, SELinux, service-manager, and user-scope chain—not a guessed
`service call` payload.

### 2. OTA/recovery is a privileged capability boundary

The PS7331 package is a signed full BLOCK OTA with fixed device/product gates
and boot-chain/system/vendor targets. That proves what a trusted recovery
executor can do, not that shell or an ordinary APK can invoke it. Native
verifier identity, AVB/rollback authority, recovery UID/domain, and caller
handoff remain incomplete in the saved host corpus. No malformed, downgrade,
symlink, traversal, sideload, recovery, or updater replay was performed.

### 3. Driver capability is not privilege acquisition

The ION/MTK source and native ELF evidence establishes several hardware-facing
surfaces. It does not establish the selected DTB/object, merged allow rule,
actual opener, caller domain, or a path from the driver effect to PackageManager,
UID 0, HOME, or kernel-memory control. The missing joins are host-only work,
not a reason to issue device-node ioctls.

### 4. “Any permission is enough” is too broad

For the practical Fire Launcher sink, an authority must survive all of the
following: protected-package enforcement, correct User-0 scope, matching
system/signature/privileged or owner authority, SELinux/service-manager
boundaries, and persistence/watchdog behavior. A permission name alone is not
evidence of a privilege transition.

  PS7331 artifact family (`P19E-*`).

- No safe ADB/API route currently closes ordinary caller → trusted identity →
  Fire-state or UID-0 sink.
- The next useful work is offline provenance/policy closure, not more random
  settings, priority, preferred-activity, or unknown Binder attempts.

- Profile/input callback caller sets and downstream consumers.
- Selected DTB/DTBO, merged TE/genfs policy, and shipped native openers for
  the remaining MTK surfaces.
- Native OTA verifier, AVB/rollback authority, and recovery UID/SELinux handoff.

- Ordinary shell/APK direct Fire Launcher enabled-state mutation.
- Ordinary-app KFT User-0/User-10 relay from existing tests.
- AmazonPackageManager facade as an automatic ordinary-to-system identity
  relay.
- Preferred HOME record alone as a replacement.
- Prewarm as a HOME/package/UID-0/partition sink.

- Unknown Binder transaction construction or fuzzing.
- `/dev/ion`, CMDQ, M4U, uinput, RPMB, USB, or other driver open/ioctl.
- Root/GhostLock/BROM/bootloader exploit attempts.
- OTA/recovery/sideload/reboot/partition-write/remount/SELinux operations.
- Fire Launcher disable/hide/suspend/uninstall/clear-data mutations.
