# Phase 21 — Broad privilege-surface residual closure

Date: 2026-08-10 (Asia/Taipei)

## Executive result

Phase 21 deliberately searched beyond Launcher. The target set was any
ordinary APK, ADB shell, exported component, system callback, OTA path, native
loader, driver-facing process, or persisted policy that could eventually
provide enough authority to change Fire package state, HOME, user 0 policy,
UID 0 state, boot/partition state, or kernel-memory/credential state.

**Confirmed, bounded:** the five host-only ledgers contain 45 normalized
records. They do not close a new complete chain of
`caller → authorization gate → accepted identity/user scope → sensitive sink`.
The only direct Fire package-state sink remains the previously known KFT/PMS
static boundary; Phase 21 did not establish a new caller, bypass, or User-0
writer.

**No device mutation:** this phase did not call a Binder service, send a
broadcast, invoke a `PendingIntent`, write Settings, install an APK, open or
ioctl a driver node, execute OTA/recovery, reboot, change package state, read
the privileged deny-list contents, attempt root, or write a partition.

The normalized machine-readable ledger is
[`phase21-caller-gate-sink.csv`](../output/tables/phase21-caller-gate-sink.csv)
and is generated by
[`build_phase21_privilege_closure.py`](../tools/scripts/build_phase21_privilege_closure.py).

## Scope and provenance

The review used preserved host artifacts only. Exact PS7331 source/image/OTA
inputs remain separate from saved 2026-08-03 device-pulled PS7330-baseline
artifacts. A matching JAR hash is not treated as proof that VDEX/ODEX,
runtime, or the complete build is identical.

Worker ledgers and their SHA-256 values are recorded in
[`sha256sums.txt`](../firmware/manifests/PHASE21-HOST-ANALYSIS-20260810/sha256sums.txt).
The worker CSV export has two unquoted comma-containing evidence fields in the
cross-surface review. The normalizer repairs those fields in memory only; the
raw worker CSV is preserved unchanged and its raw hash is recorded.

## Findings

### 已證實（bounded facts, not exploitability claims）

1. **P21D-RESOURCE-001:** the PS7331 host resource path, schema and raw JSON
   membership are closed. `packages_deny_list` contains 48 entries / 46
   unique values, and `com.amazon.firelauncher` occurs once. The raw resource
   SHA-256 is
   `16086fecbfce0a20c0b37535e25d690635d398b30d582fa6d231736dc9bdf710`.
   This proves a host seed source, not that the seed branch ran on every boot.

2. **P21D-REJECTION-003:** the saved exact-build shell package and component
   mutation attempts were rejected before the state write with
   `Security exception: Cannot disable a protected package`. Fire Launcher and
   HOME remained unchanged in the saved post-state. This confirms the
   observed gate, not a privileged bypass or the live persisted set literal.

3. **P21E-001 / P21E-002:** exact PS7331 compiled framework/services artifact
   boundaries and the already-known KFT enabled-state static sink are present.
   No new HOME writer was recovered from that boundary.

4. **P21B-006 / P21B-009:** bounded DSE code reaches a browser-default setter
   and a `WEB_SEARCH + DEFAULT` preferred-activity setter. These are distinct
   from the HOME action and are not evidence of a HOME or Fire Launcher
   replacement path.

### 高可信推論

1. **P21A-002, P21A-003, P21A-005, P21A-006, P21A-007, P21A-010,
   P21A-012:** FOSINIT registrations and callback implementations provide
   real static fan-out edges, but the missing method-local caller/authz,
   identity-clear ordering, explicit user mapping, and concrete sink joins
   prevent promotion to an ordinary-caller privilege chain.

2. **P21C-001, P21C-002, P21C-004, P21C-006, P21C-009:** ION library,
   relocation and loader-intent edges are real. Init/VINTF ownership and CIL
   authorization describe potential graphics/media/camera/storage paths, not
   proof of an executing process, arbitrary ION operation, credential effect,
   or privilege transition.

3. **P21E-003 and P21E-004:** the PS7331 OTA/update and `meta_tst`/`rpmb_svc`
   artifacts have privileged/static capabilities. Recovery identity,
   AVB/rollback authority, selected DTB/object, complete native control flow,
   and a sensitive downstream effect remain open. They are not safe device
   test targets under the current evidence.

4. **P21D-JOIN-004 and P21E-002:** host artifact identity and saved runtime
   observations are mutually consistent, but consistency is not proof that a
   low-privilege caller can reach the trusted side.

### 待驗證（host-only residuals）

- **P21A-001, P21A-004, P21A-008, P21A-009, P21A-011, P21A-013:** exact
  callback method bodies, manifest/exportedness and permission gates, sender
  identity, identity-clearing order, and concrete Settings/recovery/file/debug
  sinks are incomplete.
- **P21B-001, P21B-002, P21B-004, P21B-005, P21B-007, P21B-008,
  P21B-010:** creator-token provenance, DSE permission protection, decompiler
  branch reconstruction, PendingIntent origin, injected settings writer, and
  installer/account/user handoff remain incomplete.
- **P21C-003, P21C-005, P21C-007, P21C-008:** service-to-ELF load and runtime
  process-to-ION callsites are not closed.
- **P21D-PERSISTED-002:** `/data/system/PackageManagerDenyList` metadata and
  ACL are saved, but the `DenyListKeyPackages` literal could not be read from
  the shell evidence. It must remain unknown rather than inferred from the
  resource.
- **P21E-005, P21E-006, P21E-007:** PMS callback fan-out, current-user UI
  launch and driver-to-credential/UID0 effects remain residuals only.

### 已排除（有界）

- **P21B-003, P21B-009, P21B-011:** the recovered Vending/DSE paths contain
  no Fire Launcher target or HOME writer; their observed sinks are restore
  bookkeeping, browser default or WEB_SEARCH. This does not clear unrelated
  framework services.
- No Phase 21 result turns a library dependency, exported component,
  `startActivityAsUser`, callback registration, or generic setter reference
  into a complete privilege escalation chain.

### 因風險拒絕測試

- **P21E-008:** no runtime exploit or device operation was attempted. In
  particular, no private Binder transaction, broadcast replay, DSE bind,
  settings write, package mutation, driver open/ioctl, ION/CMDQ/M4U/RPMB
  operation, OTA/recovery execution, partition write, or kernel-memory
  operation was performed.
- **P21D-PERSISTED-002:** no privileged read, `chmod`, remount, SELinux
  bypass, Arcus refresh or deny-list replacement was attempted.
- The refusal labels are scope decisions, not negative runtime results.

## Broad target assessment

| Potential authority/sink | Phase 21 status | Safe disposition |
|---|---|---|
| Fire package/component state or HOME | only existing KFT/PMS static sink; no new complete caller/User-0 chain | host-only join; no mutation/replay |
| SettingsProvider / secure-setting writer | DSE injected writer and FOSINIT Settings callbacks are incomplete | recover key/provider/permission offline; do not write |
| User/profile or cross-user authority | callback/profile edges are bounded; no accepted ordinary caller or User-0 relation | do not create/switch users or call private APIs |
| UID 0 / SELinux transition | no Phase 21 complete transition | no exploit or policy mutation |
| OTA/recovery/boot/partition | static capability, trusted executor and acceptance gaps | no OTA, recovery, reboot or flash |
| Kernel driver / memory / credentials | ION and diagnostic partials only | no `/dev` access or ioctl |
| Browser/search/default-app side effects | DSE browser and WEB_SEARCH only | not equivalent to HOME or privilege escalation |

The broader question therefore has the same current answer as the Launcher
question: **a capability is not a reachable authority.** Until caller,
permission/SELinux gate, identity or user scope, and sensitive sink are all
closed, no device POC is justified.

## Next safe work

The highest-value follow-up remains static and narrow:

1. Reconstruct the missing FOSINIT and DSE method bodies from original smali/
   DEX, then record manifest permissions and `getCallingUid()` /
   `clearCallingIdentity()` ordering.
2. Reconcile the ION service executable-to-library loader map and selected
   DTB/object offline.
3. Preserve the deny-list distinction between resource membership, persisted
   membership and observed rejection; do not bypass the persisted-file ACL.
4. Reconcile OTA/recovery identity and AVB/rollback handoff from saved image
   metadata only.

If any future host-only join closes a public, reversible, documented API path
to a sensitive sink, it must still receive a separate safety review before a
device test. On the present evidence, no such path exists; no device-side
privilege or root test is warranted.
