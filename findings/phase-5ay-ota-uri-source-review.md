# Phase 5AY：DeviceSoftwareOTA URI／更新來源唯讀分析

## 結論先行

### 已證實

1. 目前裝置仍是 `KFTRWI/trona`、Fire OS 7.3.3.0、`PS7330.4104N`、
   Android 9/API 28；OTA 控制器位於 `/system/priv-app/DeviceSoftwareOTA`，
   是 privileged package。證據：`P5AY-DEVICE-001`、`P5AY-DEVICE-002`。
2. 既有 OTA APK 的預設更新查詢端點是
   `https://softwareupdates.amazon.com/software/inventory2`，由
   `OTASettings.getRequestUrl()` 取得；該值可由 OTA 的 Arcus remote
   configuration key `getUpdatesUrlPathAndMethod` 覆寫。證據：
   `P5AY-STATIC-002`、`P5AY-STATIC-003`。
3. 更新查詢不是把 PS7330 檔名直接寫在 APK 裡：`GetUpdatesCall` 透過
   `AuthenticatedURLConnectionWrapper` 建立 JSON `POST`，輸入包含 build
   dimensions 與已安裝套件 inventory。證據：`P5AY-STATIC-004`、
   `P5AY-STATIC-005`。
4. 伺服器回應的 `AvailableUpdatesContainer.getUrl()` 被轉成
   `PublishedUpdate.mRemoteUri`，並寫入 `PublishedUpdates.RemoteURI`；完成下載
   後另以 `PendingUpdate.LocalURI` 保存本地檔案位置。證據：
   `P5AY-STATIC-006`、`P5AY-STATIC-007`。
5. `DownloadStarter` 會把 remote URI 交給 `DNWStateObservable.getOtaDownloadUrl()`，
   再透過 `IAmazonDownloadManager.enqueue()` 排程；APK 可見的 DNW 特殊 URL
   是 `http://denali.content/content/ota?path=`，不是 PS7330 固定檔案名。
   證據：`P5AY-STATIC-007`。
6. shell 可見的共享儲存區沒有找到 PS7330/PS7331 OTA bin/zip；`/cache`、
   `/data/ota_package` 與 OTA app private data 對 shell 不可讀，因此不能把
   「看不到」解讀成「私有資料庫不存在」。證據：`P5AY-DEVICE-003`。

### 高可信推論

- 目前裝置的正式 OTA binary URL 若曾被保存，最可能位於
  `com.amazon.device.software.ota` 的 `updates.db`／相關私有狀態，或只存在
  受驗證更新查詢的回應與 Download Manager 狀態中；普通 ADB shell 無法直接
  匯出該內容。
- 7.3.3.0 source archive 對 GhostLock 的主要價值是 exact source family：
  `kernel/mediatek/4.4/kernel/locking/rtmutex.c` 與 pinned stable v4.4.146
  的 normalized SHA-256 相同，且保留修補前 `remove_waiter()` 語意。它不是
  signed `boot.img`、`Image`、`vmlinux`、preloader、LK 或 DA。
- OTA URI 分析不能補足目前缺少的 signed PS7330 kernel；它只說明「若取得
  更新查詢回應，URL 如何進入私有資料模型」，不能推出某個可下載或可刷入的
  7.3.3.0 image。

### 待驗證

- 該裝置 OTA 私有資料庫是否仍保存歷史 `RemoteURI`、已完成更新或失敗更新
  的記錄。
- 目前 remote configuration 是否曾覆寫 `getUpdatesUrlPathAndMethod`，以及
  針對該裝置／區域／OTA group 的查詢回應內容。
- Amazon 是否曾公開可合法取得、且與 `PS7330.4104N` 完全匹配的 signed OTA
  或 boot artifact。

### 無法取得證據

- 本輪沒有取得實際 PS7330 `RemoteURI`、`LocalURI`、`updates.db` 內容或更新
  回應 JSON，因為這些資料位於 shell 不可讀的 private path，而且沒有啟動
  OTA check/download。

### 因風險拒絕測試

- 沒有授予 `com.amazon.dcp.permission.DISPLAY_DEBUG_UI`。
- 沒有猜測私有 Binder transaction、繞過 app-data 權限、啟動 OTA check、下載、
  install、sideload 或改寫 `ota_disable_automatic_update`。
- 沒有讀寫 boot/LK/recovery/preloader、執行 GhostLock race、kernel memory
  write、root payload、BROM/DA、fastboot 或分割區操作。

## 靜態資料流

```text
OTASettings.getRequestUrl()
  -> SettingsManager.getString("getUpdatesUrlPathAndMethod", default endpoint)
  -> GetUpdatesCall.prepareUrlConnection()
  -> authenticated JSON POST /software/inventory2
  -> GetUpdateContainer.AvailableUpdatesContainer.url
  -> PublishedUpdate.mRemoteUri
  -> PublishedUpdates.RemoteURI in updates.db
  -> PendingUpdate.getRemoteUri()
  -> DNWStateObservable.getOtaDownloadUrl()
  -> AmazonDownloadManager.enqueue()
  -> PendingUpdate.LocalURI after download
```

`SettingsManager` also constructs an Arcus remote-configuration client and
registers device/build attributes (`dsn`, `device`, `build_version`, and, when
available, `ota_group`). That explains why the APK's default endpoint is not
enough to reconstruct a particular device's returned URL.

## 與 exact PS7330／GhostLock 的關係

The exact Amazon source archive is:

`Fire_HD10-7.3.3.0-20240730.tar.bz2`

Source URL:
<https://fireos-tablet-src.s3.amazonaws.com/7OU0BzzYt2YlM3MKwchLwgyUHM/Fire_HD10-7.3.3.0-20240730.tar.bz2>

The recovered `rtmutex.c` member has SHA-256
`c4ddac5fe820c7f07670bc332425be05b0df0400ae334a147b483f0ee9b07345`, equal to
the pinned stable v4.4.146 reference. This is strong source-level evidence that
the public 7.3.3.0 source contains the pre-fix GhostLock pattern, but it does
not reveal runtime KASLR/physmap addresses or prove the exact signed kernel was
built without an out-of-tree backport. See `P5AY-SOURCE-001` and the existing
Phase 5AV evidence.

The correct next artifact is therefore an exact, legally obtained PS7330 signed
image or a permitted OTA response export—not an inferred S3 name and not a
PS7331 image substituted into the PS7330 device.

```sh
  --apk artifacts/phase3b-ota/com.amazon.device.software.ota__0_DeviceSoftwareOTA.apk \
  --output artifacts/phase5/ota-uri-static-review-YYYYMMDD-NN \
  --dry-run

python3 tools/scripts/analyze_phase5ay_ota_uri_static.py \
  --apk artifacts/phase3b-ota/com.amazon.device.software.ota__0_DeviceSoftwareOTA.apk \
  --output artifacts/phase5/ota-uri-static-review-YYYYMMDD-NN
```

The script uses JADX in a temporary directory, refuses to overwrite an existing
output, records the input APK hash, and performs no device or network I/O. The
captured exact-device evidence is referenced rather than re-collected, so this
phase did not repeat the prior OTA residue test.
