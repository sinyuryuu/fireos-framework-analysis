# Phase 5X：Android implementation、MTK route 與 exact PS7330 可達性

## 範圍與安全界線

本輪針對使用者提出的 GhostLock、CVE-2026-43503，以及新的 MTK AEE／ATF／APEX
候選，回答「Android 中實際落在哪一層」與「這台 KFTRWI 是否有可觀察的合法入口」。

本輪只做：

- 公開官方公告與公開 source 的版本／target review；
- host-only compatibility matrix；
- exact device 的唯讀 process、package、service、init、property、node metadata、
  APEX service/path 與 HOME snapshot。

本輪沒有：

- 開啟 `/dev/sspm`、`/dev/block/by-name/spmfw`、`/dev/ion` 或其他 device node；
- 讀取 block device、boot image、preloader 或 partition；
- 觸發 AEE、ATF、futex、networking、CMDQ、ION、Bluetooth 或 modem 輸入；
- 執行 exploit、native payload、root 工具、BROM/DA、fastboot、recovery、remount；
- 修改套件、設定、SystemUI、HOME、boot chain 或其他裝置狀態。

## Android implementation map

「Android implementation」不是一種統一的 APK。每個候選的入口不同：

| 候選 | Android 實作層 | 與本機的關係 | 判定 |
|---|---|---|---|
| GhostLock / `CVE-2026-43499` | Android native code 可經 Bionic／`syscall` 進 futex PI；實際錯誤在 Linux `rtmutex` | Fire source/config 有 futex/rtmutex 家族，但 signed PS7330 backport、compiled layout 與觸發條件未確認 | 高可信 source applicability；不是 root 證明 |
| `CVE-2026-43503` | Linux networking `skb`／shared-fragment 路徑，不是 Android framework 或 APK | Phase 5U 的 exact defconfig review 顯示主要 duplicate/TEE/netfilter gate 未被觀察為啟用 | 已確認為與 GhostLock 無關；不新增 live trigger |
| `CVE-2025-20765` | MediaTek AEE daemon 的 userspace race/double-free；AEE 可能與 kernel crash-reporting／MRDUMP 整合 | MTK 公告列 MT8183，但沒有列 Android software version；本次 runtime 只有 kernel AEE worker threads，沒有觀察到 userspace AEE daemon | Strong evidence，僅 scope/runtime；不可推導 shell root |
| `CVE-2024-20021` | MediaTek ATF SPM／secure firmware 與 Android device-node 邊界 | 公告列 MT8183，但 software scope 是 Android 12–14，且要求已有 System privilege；本機是 Android 9 shell UID 2000 | 已確認 applicability mismatch；只保留 node metadata |
| `CVE-2023-45779` | Android APEX package/update service 與高權限 APEX 載入 | 公開案例是 Android 13 Lenovo Tab M10 Plus；本機 `ro.apex.updatable` 為空、APEX 路徑／套件不存在、`apexservice` 不存在 | 已確認 runtime-surface mismatch |
| `CVE-2026-3499` | 使用者提供的候選識別碼，尚不能建立與 GhostLock 的對應 | 既有 public review 將 GhostLock 識別為 `CVE-2026-43499`；`3499` 不能作為本機 kernel implementation 名稱 | 未驗證識別碼；拒絕由此推導操作 |

## Exact-device runtime observations

### AEE／MTK userspace

唯讀 process/package/service/init 採樣顯示：

- kernel threads 有 `[gpu_aee_wq]`、`[mali_aeewp]` 與 `[SSPM_WQ]`；
- 沒有名稱可辨識為 userspace `aee`、`aee_dumpstate` 或 AEE daemon 的 process；
- package list 沒有 AEE／exception daemon package；
- service list 沒有 AEE／ATF／SPM userspace service；
- init path 採樣只命中標準 `dumpstate.rc`，沒有命中 AEE/ATF/SPM daemon rc。

這證明「目前正常 runtime 中沒有被 shell 直接看見的 AEE daemon endpoint」，不證明
filesystem 中不存在不可讀 binary，也不證明已安裝 binary 的 patch status。

MediaTek 2025-12 bulletin 將 `CVE-2025-20765` 描述為 AEE daemon double-free，
可能因 race 導致 system crash，且 affected chipset 包含 MT8183；該列沒有給出
Android software version。這是 external scope，不是 exact PS7330 exploitability。

### ATF／SPM

本機只保存 node metadata：

```text
/dev/sspm                  cr--r----- root system u:object_r:sspm_device:s0
/dev/block/by-name/spmfw  -> /dev/block/mmcblk0p11
```

這裡沒有 `open()`、`read()`、`ioctl()` 或 block-device 操作。`/dev/sspm` 的
存在只說明 kernel/firmware surface 可見，不表示 shell 有權限或存在可用 transaction。

MediaTek 2024-05 bulletin 的 `CVE-2024-20021` 同時有 MT8183、Android 12/13/14
software scope 與 System-privilege 前提；本機 Android 9／shell UID 不符合，故不把
node 可見性當成可利用性。

### APEX

本次 exact runtime 保存了：

- `getprop ro.apex.updatable`：空值；
- `/system/apex`、`/vendor/apex`、`/product/apex`：不存在；
- package list：沒有 `apex`／`vndk` package；
- `cmd apexservice --help`：`Can't find service: apexservice`，exit code 20。

因此 Android 13 APEX test-key advisory 的 Android implementation 在這台 Android 9
上沒有被觀察到。沒有安裝、更新或替換 APEX。

## 公開 Android／MTK source review

### KoCleo `mtk-easy-su`

目前公開 master 的 pinned head 是
`8c6871ac7c15b8e98a47e25c35ab93b87e260475`（2025-11-07）。README 描述的是
Magisk／`mtk-su` bootless-root wrapper，並警告 2020-03 後 firmware 可能阻擋
`mtk-su`；測試清單沒有 `KFTRWI`、`trona` 或 `MT8183`。本機同一 payload 的失敗已
由既有 Phase 5 證據封存，因此本輪不重跑。

**判定：已確認，route already disproved on this build。** 新 commit 沒有提供
exact PS7330 Android implementation、kernel profile 或新的低風險入口。

### LauncherHijack

目前 master pinned head 是
`f79aee3ddd10c053d6d7c55d6f2fc29436001537`（2026-01-25）。README 已標示專案
deprecated，並指出 Amazon 將 package name 放入 FireOS blocked app list；HELP 文件
仍保留手動 Accessibility 流程，也保留「破壞 default launcher」的高風險路線。

高風險的 default-launcher corruption 路線明確可能留下沒有可用 Launcher 的 user
狀態，且文件警告可能無法由該 user account 修復；本輪標記為**因風險拒絕測試**。
既有 exact controlled run 已得到 0/30 handoffs，因此本輪只做 source/runtime review，
不重跑。

### Generic MTK BROM／DA／preloader

公開 `mtkclient` 文件是 boot-chain 工具，涉及 BROM/DA、讀寫與 unlock 類能力；它
不是 Android userspace implementation。現有本機只有相鄰 PS7331 boot-chain image，
不是已安裝的 PS7330。沒有 matching loader、DA、SLA/DAA、rollback 與 recovery set，
故不進行 handshake、upload、unlock 或寫入。

### Android public PoC 的正確定位

既有 public-source review 的 Android projects 主要是 detector、target/profile
generator 或其他裝置的 kernel port。它們可借鑑「依 exact boot、kernel、SoC、layout
重新建立 profile」的方法，但不提供本機可直接執行的 APK/root payload。這一輪沒有
找到新的 `KFTRWI/trona/MT8183/PS7330` Android implementation。

## 結論

- **已證實：** exact device 仍是 Android 9/API 28、MT8183、PS7330，HOME 仍解析
  到 Fire Launcher；本輪沒有裝置狀態變更。
- **已證實：** Android implementation 必須按層分開：GhostLock 是 native syscall
  到 kernel；AEE 是 vendor daemon／crash-reporting boundary；ATF/SPM 是 secure
  firmware boundary；APEX 是 Android package/update boundary。
- **Strong evidence：** `CVE-2025-20765` 的 MT8183 scope 與 AEE daemon 名稱值得
  記錄，但目前 runtime 沒有 shell 可見 AEE daemon endpoint，也沒有 Android 版本
  或 exact PS7330 binary 證據；不能當成 root 路線。
- **已確認：** `CVE-2024-20021` 與本機 Android 9／shell privilege 不匹配；
  `CVE-2023-45779` 的 APEX runtime 在本機不存在。
- **已排除：** 將 `CVE-2026-3499` 當 GhostLock；將 `CVE-2026-43503` 當
  GhostLock；把 MTK source、其他 Android 裝置 PoC、PS7331 image 或 generic
  `mtkclient` 當成本機 payload。
- **因風險拒絕測試：** AEE race、ATF/SPM node、APEX install、futex PI、network
  trigger、BROM/DA、preloader/LK、fastboot、remount、partition write，以及
  LauncherHijack 的 default-launcher corruption route。

## 下一個仍有研究價值的最小目標

只剩兩個合理的 host-only 方向：

1. 取得與已安裝 PS7330.4104N 完全匹配、可驗證來源的 vendor AEE／ATF／APEX
   artifact，做離線 patch／symbol／permission comparison；
2. 若無法取得 exact artifact，將 `CVE-2025-20765` 保留為「external scope only」
   並正式結案，不再以它設計 live trigger。

目前沒有足夠證據支持新的無 Root Android root 或 HOME replacement。這不是說
   PS7330 絕對沒有未公開漏洞，而是現有 Android implementation 與 exact-device
   runtime 證據不足以安全、可重現地執行任何新路線。
