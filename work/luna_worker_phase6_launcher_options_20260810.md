# Phase 6 Launcher 替代方案與既有測試結果整理

日期：2026-08-10。範圍只涵蓋 `findings/`、`adb/`、`mutation-tests/`、`tools/`、`artifacts/` 內的既有證據。本整理沒有接觸裝置，也沒有停用、隱藏、suspend、force-stop、clear Fire Launcher，沒有 root、未知 Binder、OTA/OOBE replay 或裝置狀態修改。

## 結論摘要

- **Confirmed：** 目前沒有已驗證的普通 sideload APK 或公開 ADB 路徑能取代 User 0 的形式 HOME resolver；現況仍是 `com.amazon.firelauncher/.Launcher`、priority 50。依據 `P3A-RUN-*`、`P2-HOME-*`、`6CQ-*`；`findings/home-priority-experiment.md`、`findings/home-preferred-state.md`、`findings/phase-6cq-dpm-persistent-preferred-boundary.md`。
- **Confirmed / Strong evidence：** Accessibility redirect 與 Lock Task 可讓第三方 Activity 成為可見 foreground，但 resolver 仍是 Fire；這不是 HOME writer。依據 `F-109`、`F-084`、`6CL-*`、`6CM-*`；`findings/phase-6cy-ms-accessibility-foreground-replication.md`、`findings/phase-6hb-ms-accessibility-reboot-persistence.md`、`findings/phase-6cl-manifest-locktask-boundary.md`。
- **Confirmed：** child/KFT 路徑確實能使 Tahoe 成為 child user HOME，且 Fire 的 package state 只在該 child user 生效；它不是 User 0 替代方案。依據 `PHASE6CB/CC`、`6AY-KFT-*`；`findings/phase-6cb-gui-child-profile-kft-lifecycle.md`、`findings/phase-6cc-adb-child-home-activation.md`、`findings/phase-6ay-kft-device-verification.md`。
- **Confirmed / Static only：** OOBE/OTA、ProductPolicy、KFT writer 都是受信任生命週期或 system-server 路徑；既有 artifacts 沒有證明可由普通 caller 安全觸發。依據 `6AG/6BP/6U`、`6CE`、`6MH`；`findings/phase-6ag-boot-after-system-ota-research-item.md`、`findings/phase-6bp-ota-post-install-path-audit.md`、`findings/phase-6ce-product-policy-firelauncher-boundary.md`、`artifacts/phase6mh-package-state-writers-20260810-01/summary.json`。
- **下一候選：** 僅建議進行 **主機端、唯讀的 package-state writer target/data-flow 收斂**：針對 `phase6mh` inventory 中尚未分類的 `other_state_writer` 與 `amazon_product_policy` callsite，確認是否有「Fire Launcher + User 0 + HOME」三者同時成立。這不是裝置 workaround，也不應呼叫 setter。若 target、caller gate 或 user scope 仍不成立，候選即關閉；若已經在其他 artifact 完整覆蓋，則沒有新的安全候選。

## 尚未重複且安全的下一候選

候選名稱：**Phase 6MH-RO：package-state writer target/data-flow closure**。

理由：`artifacts/phase6mh-package-state-writers-20260810-01/summary.json` 是新的 host-only inventory（21 callsites、10 application setters、11 component setters），但其自身將結論限定為「callsite inventory only」。其中 KFT 三筆與 ProductPolicy 四筆已由既有 `6AY`、`6CB/CC`、`6CE` 覆蓋到主要邊界；尚未把其餘 `other_state_writer` 逐一閉合到「target package、userId、caller/permission、是否 HOME 相關」。這是目前最小、低風險且不重複的資訊增益。

最小驗證條件：

1. 只讀 `writer-calls.csv`、相同輸入 VDEX/disassembly 與已存 source；不接 ADB。
2. 對每筆 `other_state_writer`／ProductPolicy callsite 標出 target 是否可達 `com.amazon.firelauncher`、是否固定 User 0、是否由 system-server/trusted policy 觸發、是否與 HOME/resolver 有 data-flow edge。
3. 輸出只能是 host-side CSV/Markdown/sha256；不呼叫 PackageManager setter、不送 Binder、不改 package/settings/user/policy。
4. 若沒有同時成立的 Fire + User 0 + HOME edge，結論為 **Disproved/Unknown**（依證據完整度），並明確關閉此候選；若有 edge，也只能標 **Hypothesis/Probable**，下一步仍須另行授權，不能直接在 stock device 觸發。

## 最終判定

以「替代 User 0 Fire HOME resolver 並阻止其恢復」為成功標準：**目前沒有安全、未重複且已可直接執行的下一個裝置候選**。最接近且已實證的是 Accessibility foreground fallback；最完整的 child HOME 是 user-scoped KFT lifecycle；兩者都不符合 User 0 formal HOME replacement。下一工作應停留在上述主機端 writer/data-flow closure；若該 closure 沒有新 target，應明確結束 launcher workaround 搜索，而不是升級到未知 Binder、OTA/OOBE replay、root、kernel、SELinux 或 Fire package-state mutation。
